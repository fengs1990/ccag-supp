### 9. sys_master_data 主数据参考表

**用途：** 存储系统中各类主数据的参考数据项及其代码值，用于主数据字段的合法性校验和下拉选择。

**对应需求：** 模板管理 - 指标配置（主数据下拉字段类型）

| 列名 | 类型 | 长度 | 可空 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| id | BIGINT | — | 否 | — | 主键，自增 |
| category | VARCHAR | 64 | 否 | — | 分类（如：公共信息、财管运行、产权管理等） |
| data_name_cn | VARCHAR | 128 | 否 | — | 参考数据中文名（如：国家和地区、币种） |
| data_name_en | VARCHAR | 128 | 否 | — | 参考数据英文名（如：DIM_COUNTRY_AREA、DIM_CRNCY） |
| code_value | VARCHAR | 64 | 否 | — | 代码值（如：AL、USD、CNY） |
| code_name | VARCHAR | 256 | 否 | — | 代码值名称（如：阿尔巴尼亚、美元、人民币元） |
| code_desc | VARCHAR | 512 | 是 | NULL | 代码值描述（扩展说明信息） |
| standard_source | VARCHAR | 256 | 是 | NULL | 标准来源（如：GB/T 2659.1-2022） |
| status | INT | — | 否 | 1 | 状态：1=生效，0=失效 |
| sort_order | INT | — | 否 | 0 | 排序序号 |
| create_by | VARCHAR | 64 | 否 | — | 创建人 |
| create_time | DATETIME | — | 否 | CURRENT_TIMESTAMP | 创建时间 |
| update_by | VARCHAR | 64 | 是 | NULL | 最后修改人 |
| update_time | DATETIME | — | 是 | NULL | 最后修改时间 |

**索引：**
- 主键：`id`
- 唯一索引：`(category, data_name_en, code_value)` （防止同一参考数据下代码值重复）
- 普通索引：`(category, data_name_en, status)` （用于查询某个参考数据的有效代码值列表）
- 普通索引：`(data_name_en, status)` （用于按参考数据英文名查询）

**设计说明：**
1. **层级关系**：category（分类） → data_name_cn/data_name_en（参考数据） → code_value/code_name（代码值）
2. **数据导入**：从Excel批量导入，每行对应一个代码值记录
3. **查询场景**：
   - 根据分类查询所有参考数据：`WHERE category=? AND status=1 GROUP BY data_name_en`
   - 根据参考数据查询所有代码值：`WHERE data_name_en=? AND status=1 ORDER BY sort_order`
   - 验证代码值合法性：`WHERE data_name_en=? AND code_value=? AND status=1`
4. **与模板字段关联**：模板字段表中的 `masterDataType` 对应 `data_name_en`，数据录入时的值需在对应的 `code_value` 中存在
5. **状态管理**：`status=0` 表示该代码值已废弃，不再用于新数据录入，但历史数据保留
6. **排序**：通过 `sort_order` 控制下拉选项的显示顺序

## 二、模板管理模块

### 10. ccag_supp_template_group 模板分组表

**用途：** 存储模板分组信息，支持普通分组和主从分组。主从分组中第一个模板为主模板，后续为从模板。分组的字段配置和校验规则通过 `ccag_supp_template_field` 和 `ccag_supp_validate_rule` 表关联存储。

**对应需求：** 模板管理 - 模板分组

| 列名 | 类型 | 长度 | 可空 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| id | BIGINT | — | 否 | — | 主键，自增 |
| group_code | VARCHAR | 64 | 否 | — | 分组编码，全局唯一 |
| group_name | VARCHAR | 128 | 否 | — | 分组名称 |
| group_desc | VARCHAR | 512 | 是 | NULL | 分组描述 |
| group_type | VARCHAR | 16 | 否 | 'NORMAL' | 分组类型：NORMAL=普通分组，MASTER_SLAVE=主从分组 |
| org_code | VARCHAR | 64 | 否 | — | 所属组织编码 |
| status | INT | — | 否 | 0 | 状态：0=草稿，1=已发布 |
| remark | VARCHAR | 512 | 是 | NULL | 分组说明 |
| create_by | VARCHAR | 64 | 否 | — | 创建人 |
| create_time | DATETIME | — | 否 | — | 创建时间 |
| update_by | VARCHAR | 64 | 是 | NULL | 最后修改人 |
| update_time | DATETIME | — | 是 | NULL | 最后修改时间 |
| del_flag | INT | — | 否 | 0 | 删除标记：0=正常，1=已删除 |

**设计说明：**
- 分组发布后（status=1）不可编辑，只能删除
- 分组的字段配置存储在 `ccag_supp_template_field` 表中（template_id=NULL，group_id=分组ID）
- 分组的唯一性校验规则存储在 `ccag_supp_validate_rule` 表中（template_id=NULL，group_id=分组ID）
- 分组字段和规则在模板选择分组时自动复制到模板下

- 模板发布时系统自动创建500字段大宽表，表名存储在 `data_table_name` 字段
- 物理表的字段映射通过 `ccag_supp_field_column_mapping` 表记录

**二、固定500个业务字段列**

| 列名 | 类型 | 长度 | 可空 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| column1 | VARCHAR | 2000 | 是 | NULL | 业务字段1 |
| column2 | VARCHAR | 2000 | 是 | NULL | 业务字段2 |
| column3 | VARCHAR | 2000 | 是 | NULL | 业务字段3 |
| ... | VARCHAR | 2000 | 是 | NULL | ... |
| column500 | VARCHAR | 2000 | 是 | NULL | 业务字段500 |

**设计说明：**

1. **大宽表策略**：
   - 所有业务字段统一使用 `VARCHAR(500)` 类型
   - 数值类型、日期类型的数据以字符串形式存储
   - 应用层负责类型转换和格式校验
2. **字段映射机制**：
   - 通过 `ccag_supp_field_column_mapping` 表记录字段与列的映射关系
   - 示例：模板字段 `产品代码` 映射到 `column1`，`销售额` 映射到 `column2`
   - 不同模板的同一列可以存储不同含义的数据
4. **多租户隔离**：
   - 通过 `org_code` 字段实现数据隔离
   - 查询时必须加 `org_code` 条件，确保权限控制
5. **主从模板支持**：
   - 主从模板数据存储在同一张物理表
   - 通过 `is_master_data` 字段区分
   - 从模板填报时先加载主模板数据（禁止编辑）
6. **性能优化**：
   - 索引 `(doc_id, row_no)` 支持按单据快速查询
   - 索引 `(org_code, account_period)` 支持按组织账期查询
   - 索引 `(template_code, org_code, data_status)` 支持统计查询

**索引建议：**
```sql
-- 主键索引
PRIMARY KEY (id)

-- 单据查询索引
INDEX idx_doc_id (doc_id, row_no)

-- 权限过滤索引
INDEX idx_org_period (org_code, account_period)

-- 统计查询索引
INDEX idx_status (data_status, validate_status)
```

**设计说明：**
1. **附件类型区分**：通过 `attach_type` 区分单据级佐证附件和字段级附件

   - 通过 `(doc_id)` 查询单据的所有附件
   - 通过 `(doc_id, attach_type='DOC')` 查询单据的佐证附件
   - 通过 `(doc_id, data_row_no, field_code)` 查询某行某字段的附件列表
5. **锁定机制**：`is_locked=1` 的附件不可删除，用于已归档单据的附件保护

## 核心设计亮点

1. **系统管理模块完整实现**：
   - 完整的RBAC权限体系（用户、角色、菜单、接口）
   - 支持多角色、动态权限配置

2. **模板下发机制重构**：
   - ❌ 取消副本模板机制，避免数据冗余
   - ✅ 通过 `ccag_supp_template_org_rel` 记录下发关系
   - ✅ 一个模板可下发给多个组织
   - ✅ 二级单位扩展字段独立存储

3. **大宽表设计（核心创新）**：
   - ✅ 固定50个业务字段列（column1~column50）
   - ✅ 统一使用 VARCHAR(500) 类型，应用层负责类型转换
   - ✅ 通过 `ccag_supp_field_column_mapping` 表记录字段与列的映射关系
   - ✅ 避免频繁的 DDL 操作（ALTER TABLE）
   - ✅ 支持字段复用：字段删除后，列可被后续字段重新分配

4. **字段列映射机制**：
   - 模板发布时自动为集团标准字段分配列（column1、column2...）
   - 二级单位添加扩展字段时从未使用的列中分配
   - 最多支持50个字段（集团标准 + 所有二级扩展 ≤ 50）
   - 通过 `org_code` 区分集团字段映射和二级单位扩展字段映射

5. **多租户数据隔离**：
   - 集团和所有二级单位数据存储在同一张宽表
   - 通过 `org_code` 字段实现数据隔离
   - 查询时必须加 `org_code` 条件确保权限控制

6. **主从模板支持**：
   - 主从模板数据存储在同一张宽表
   - 通过 `is_master_data` 字段区分
   - 从模板填报时先加载主模板数据（禁止编辑）

7. **非周期模板支持**：
   - 通过 `fill_cycle=none` 实现非周期模板
   - 归档后支持追加补录
   - 通过审批流水表追溯历史审批记录

8. **灵活的审批流程**：
   - 支持单人审核、多级串行、按组织自动分派
   - 支持超时处理机制
   - 独立的流程和节点配置表

9. **质量看板快照机制**：
   - 定时生成快照数据，提升查询性能
   - 支持按企业、业务域、模板多维度统计

10. **完整的审计追踪**：
    - 所有操作留痕，支持数据变更快照对比
    - 操作日志不可删除，仅允许 INSERT

## 大宽表设计优势总结

| 对比项 | 动态DDL方案 | 大宽表方案（当前） |
|--------|------------|------------------|
| 字段扩展 | 需要ALTER TABLE | 只需插入映射记录 |
| DDL操作 | 频繁，可能锁表 | 零DDL操作 |
| 性能影响 | 可能影响线上 | 无影响 |
| 字段复用 | 不支持 | 支持，删除后可复用 |
| 实施难度 | 复杂 | 简单 |
| 数据类型 | 严格匹配 | 统一字符串，应用层转换 |
| 查询复杂度 | 低（直接字段名） | 中（需JOIN映射表） |
| 扩展上限 | 数据库列数上限 | 固定50列 |
